# A changed release artefact has readers in other repos

Adding the launcher tgz line to `SHA256SUMS` was correct here, but vibead-ai's `/install` release guard (`scripts/check-install-release.mjs`) parses the same file and refused the new line, which would have blocked the next `install.json` pin. Before changing the name, format or contents of any release asset (`SHA256SUMS`, archive names, `.sha256`, the tgz), `git grep` the asset name in vibead-ai and vibead/vibead as well as here (installers, tap job, guards, tests), and land or link the matching change in the same handoff. Also: once a file is signed and then published, publish the signed bytes (here `npm publish ./vibead-cli-<v>.tgz`), not a fresh build, and compare rebuilt archives by their uncompressed content, because gzip output varies with the zlib build.
