# The workflow token can't see draft releases at contents:read

GitHub shows draft releases only to tokens with push access, so a job that views or downloads a DRAFT with the workflow token at `contents: read` gets "release not found"; release.yml's `check` would have failed and nothing would have published. Give every job that reads a draft `permissions: contents: write` at job level (the workflow default stays `read`; `install/test/workflows.test.mjs` enforces it), and prove workflow permissions with the real `GITHUB_TOKEN` in a temporary read-only PR job, not with a local replay on your own token, which has push access and hides the problem. Also: publishing a draft never moves an existing tag (`target_commitish` is used only when the tag is missing). (cli#37, QA R2-1/R2-2; https://docs.github.com/en/rest/releases/releases)
